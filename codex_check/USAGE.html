Codex Session Sync

把 Codex Desktop 的本地会话导出到同步盘，再在另一台设备导入继续使用。

这个工具只同步会话文件，不同步登录态。两台设备都需要各自已经登录 Codex。导入前建议关闭 Codex Desktop。

适合做什么

用于在两台设备之间迁移或同步 Codex Desktop 历史会话，让目标设备的 Codex 原生会话列表尽量能看到并继续这些 thread。

会同步
  • session JSONL 文件
  • session_index.jsonl 条目
  • 少量 thread 状态
不会同步
  • 认证文件
  • SQLite 数据库
  • 插件、缓存、日志

第一次配置

先写入一次配置，之后就可以使用短命令。把 D:\codex-session-sync 换成真实同步目录。

codex-sync init --codex-root "%USERPROFILE%\.codex" --sync-dir "D:\codex-session-sync" --project "C:\Users\hyperchain\Desktop\AI学习\i-do-love" --scope project --max-backups 10

默认配置文件位于：

C:\Users\hyperchain\Desktop\AI学习\i-do-love\codex_check\codex-sync.json
--sync-dir 必须是真实目录。不要把 你的同步盘目录 或 <同步目录> 这种占位文字直接复制进去，工具会拒绝。

日常同步流程

  1. 在设备 A 关闭 Codex Desktop。
  2. 设备 A 执行 codex-sync push。
  3. 等待 OneDrive、Syncthing、NAS 或移动硬盘完成同步。
  4. 在设备 B 关闭 Codex Desktop。
  5. 设备 B 执行 codex-sync diff 查看差异。
  6. 设备 B 执行 codex-sync pull --dry-run 预演导入。
  7. 确认报告没问题后执行 codex-sync pull。
  8. 重新打开 Codex Desktop。

常用命令

codex-sync doctor
codex-sync push
codex-sync diff
codex-sync pull --dry-run
codex-sync pull
codex-sync status
codex-sync rollback

不安装时，把 codex-sync 换成完整的 run_sync.cmd 路径即可。

差异和冲突

codex-sync diff 会显示：

  • matching：两边都有且内容一致。
  • remote_only：同步盘有、本机没有，pull 后会新增。
  • local_only：本机有、同步盘没有，不会被 pull 删除。
  • conflicted：两边 thread id 相同但内容不同。

直接导入 zip 时可以选择冲突策略：

codex-sync import "<导出包.zip>" --conflict skip
codex-sync import "<导出包.zip>" --conflict overwrite
codex-sync import "<导出包.zip>" --conflict keep-both
  • skip：默认策略，不覆盖本机冲突会话。
  • overwrite：用导出包里的会话覆盖本机同 id 会话。
  • keep-both：保留本机会话，把导出包会话复制成新的 thread id。

出问题怎么办

每次正式导入前都会备份当前会话状态：

%USERPROFILE%\.codex\session-sync-backups\<timestamp>\
%USERPROFILE%\.codex\session-sync-last-import-report.json

如果导入后会话列表异常，可以回滚最近一次导入：

codex-sync rollback

导入 zip 时工具会拒绝不安全路径，例如 ../ 或绝对路径，避免导出包写到 .codex 之外。
